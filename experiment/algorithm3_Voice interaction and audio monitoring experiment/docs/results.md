### 3.1 Deployable sound-event model (`homeease train-sound`, class mapping v2)

Run `20261008-003505_audio_A2b_sound_model_01e89411b8`, package `models/audio_sound/sound_events/v2/` (83 kB of weights plus
`meta.json`, needs `models/audio/yamnet/yamnet.onnx`). Folds 1-4 are dev, fold 5 (466 windows, 212 groups) is the test fold: no fit or candidate choice used it, but the cut-off rule was changed once after the test result of a first attempt had been
seen (the "two attempts" bullet below), so fold 5 was scored twice, not once.

* Candidate chosen on dev (out-of-fold macro-F1): YAMNet embedding + logistic regression 0.675; RF 0.645; statistics + logistic regression 0.601; CNN 0.575.
* UNKNOWN cut-offs from out-of-fold dev predictions, rule "lowest cut-off with dev precision >= 0.90": DAILY 0.52, ABNORMAL 0.91, IMPACT 0.99; HELP cannot reach 0.90 precision on dev
  (the VIVAE confusion above) and falls back to the cut-off with the best dev F1, 0.42 (dev precision 0.50, recall 0.68).
* Test fold: macro-F1 0.658 (95% group-bootstrap CI 0.541-0.819; 0.660 without cut-offs), 77% of windows get a class, accuracy on those 0.838.
  HELP recall 0.610 [0.502, 0.708] and precision 0.575 [0.470, 0.673] on 82 HELP windows (FSD50K screams 0.676 of 34, VIVAE fear/pain 0.562 of 48; false HELP on VIVAE non-HELP 0.229 of 144, on ESC-50 0.021 of 191, on LibriSpeech 0.000 of 30; the ESC-50 and LibriSpeech rates are not specificities for short events, see the padding bullet below);
  DAILY precision 0.923 / recall 0.715 (n=302); ABNORMAL 0.935 / 0.408 (n=71); IMPACT 0.857 / 0.545 (n=11, too few for a stable rate).
* **Two attempts, so fold 5 was scored twice.** The first attempt (`20261008-002335_audio_A2b_sound_model_2b3d962b34`) used "highest dev precision" as the fallback for an unreachable target, which put the HELP cut-off at 0.99
  and gave HELP recall 0.061 (macro-F1 0.539) on the test fold. The degenerate cut-off was visible on dev data alone (target not met, cut-off at the grid edge), so the fallback was changed to "best dev F1"
  and the model retrained (cut-off 0.42, recall 0.610, macro-F1 0.658). The new rule is derived from dev data only, but the first test result had been seen when it was chosen; whether that result motivated the change cannot be shown. Both runs stay in the record.
  The A2 four-class headline candidate in the summary table is chosen on the pooled test folds, which is optimistic for the same reason.
* **The HELP rates depend on how common HELP is.** Test fold: 82 of 466 windows (17.6%) are HELP. Recall 0.610 and a false-HELP rate of 37 of 384 non-HELP windows
  (9.6% [7.1, 13.0]; 22.9% on VIVAE non-HELP voice, 33 of 144) give precision 0.575 at this share. The same two rates give precision
  25% if 5% of the windows were HELP, 6.0% at 1% and 0.6% at 0.1%: at a realistic prevalence nearly every HELP hint would be false. The benchmark ratio is not a general property, and no
  false-alarms-per-hour measurement exists (it needs continuous household recordings).
* **The 2-second window of a short clip is mostly padding (not controlled for).** Clips under 2 s (VIVAE, FSD50K) sit in a window padded with -50 dB noise; the loudest 2 s of a 5 s ESC-50 or LibriSpeech clip does not. The share of quiet
  frames in the window alone separates HELP from the ESC-50 and LibriSpeech non-HELP windows with an AUC of 0.785 (inside VIVAE 0.509, inside FSD50K 0.265, a reversed cue there),
  so the model can use window shape instead of sound. Probe with the shipped model: the same 191 ESC-50 fold-5 clips, cut to their loudest 0.85 s and centred in the same padded window, are called HELP in 19 cases
  (9.9% [6.5, 15.0]) instead of 4 (2.1%), UNKNOWN rises from 22 to 49 and DAILY falls from 134 to 92
  (the probe also truncates the content, so it shows that the model reacts to duration and padding, not how large the effect is in a home). The false-HELP rate on ESC-50 quoted above is therefore not a specificity for short events. A model trained
  and evaluated with padding-matched windows has not been made.
* **One Freesound recording can sit in two folds.** 14 recordings occur both as an ESC-50 source file and as an FSD50K clip (none of them HELP); 11 of them landed in different folds, because the group check works inside one corpus,
  so 6 of the 466 test windows have a sibling of the same recording in training. Dropping the 14 duplicate ESC-50 clips changes the A2 four-class YAMNet macro-F1 from 0.6772 to 0.6761 (-0.0011); eight random drops of the same class mix give -0.0031 to +0.0023, so the effect is not distinguishable from noise. Reported, not repaired: moving a group would change every fold and every published A2 number.
* The saved package reproduces the evaluated probabilities (max difference 5e-7 on 13 test windows after reload through `load_sound_classifier`) and drives `SoundMonitor` on a scene of real
  held-out clips (plumbing check, not accuracy).

The 38 self calls for help are 28 distinct phrases (14 per language, 7 families each) plus 10 of them again at 5 dB noise, so the per-clip intervals above are narrower than the evidence really is.
The two self calls for help read as REASSURANCE are mixed sentences ("I'm fine, but ...") whose help half the ASR dropped. The 17 TV / visitor lines read as REASSURANCE all really contain reassuring words (0 recognition errors):
the intent is evidence about the words, not about the speaker. That is why branch A needs the voiceprint, and why a reply never cancels anything.

What helped and what did not:

* **Rule v2 helped, by far** (same ASR): dev 0.605 -> 0.935, test 0.480 -> 0.894; self calls for help missed 23 -> 5 of 38. It fixes what v1 got wrong: Whisper writes Mandarin in Traditional characters (v1 never matched them),
  "I'm not hurt" was read as HELP, and everyday cues (ouch, slipped, stuck, \u8dcc\u5012, \u52a8\u4e0d\u4e86) were missing. The script fix alone (v1 on Simplified text) gave 0.558 on test. **Caveat that limits this claim:** the v2 lexicon was written by the author of the phrase bank with both
  splits in sight. 13 of the 51 cues that fire at all fire only on test wording. Post-hoc diagnostic (`posthoc_lexicon_ablation.md` in the run directory): with those 13 cues switched off the test macro-F1 is 0.834 and 13 of 38 self calls for help are missed
  (reference text without ASR: 0.990 -> 0.914; the diagnostic re-scores the saved transcripts with its own routine, whose value for the full lexicon, 0.892, differs from the 0.894 above in the third decimal).
  Switching off only those 13 cues is not a lower bound: the cues that fire on both splits were also written with both splits in sight. A probe with wording the author never saw (`config/audio_unseen_probe.yaml`: 20 help and 15 reassurance phrases written by one reviewer afterwards, text only, no ASR, not a random sample) is harsher: rule v2 reads 6 of 20 help phrases as HELP (30% [15, 52]; it misses "Please come quickly", "I slid off the chair", "My back is killing me", "I blacked out for a bit" and 10 more) and 6 of 15 reassurance phrases as REASSURANCE, one of them ("I just sat down on the floor, all good") as HELP. The dev and test phrases are also closer than the lint implies: 9 cross-split pairs overlap in at least half of their words (Jaccard 0.5; the lint refuses only 0.6). Read 0.894 and 5 of 38 as upper bounds for unseen wording; the real figure for new phrasings is unknown and probably much lower. The same switch-off for the 9 dev-only cues costs the dev score 0.940 -> 0.898.
* **Decoding bias (hotwords / initial prompt) did not help reliably and is not adopted.** On dev it looked good (best deployable cells 0.960-0.961 against 0.935 without; missed calls 7 -> 2-3). On test the dev-selected hotwords cell was *worse* than its unbiased neighbour
  (0.875 vs 0.894; 7 vs 5 missed; both within noise). Worse, hotword biasing makes Whisper-tiny write the bias vocabulary on non-speech that passes the energy VAD (appliance noise, 12 clips): 1 of 12 clips came out as HELP, 1 as REASSURANCE (first run: 3 and 2), and
  these decodes took 5-12 s each (first run: up to 15 s; p95 9.0 s against 1.2 s with plain decoding, first run: 12.1 s against 1.5 s). The initial prompt gave 1 of 12 as HELP (first run: 0 of 12) with a p95 of 4.5 s; Whisper base with hotwords gave 4 of 12 (first run: 1 of 12).
  Twelve clips cannot rank the cells and the rates moved between the runs, but every biased cell had at least one clip read as HELP in at least one run, while plain decoding never did (0 of 12 here, 0 of 12 in the first run): it writes short hallucinations such as "Thank you." or "See you next time!", read as OTHER or UNCERTAIN.
  The choice between the dev-selected cell and its unbiased neighbour was made after the test numbers were known; it is a post-hoc decision, supported by the dev/test disagreement and by the hallucination probe, and it keeps the product at its existing ASR settings.
* **Whisper base instead of tiny: no reliable gain, about twice the latency, heavier tails.** Dev, no bias: 0.951 vs 0.935 and 5 vs 7 missed, median 1.21 s vs 0.60 s. Test (only measured with hotwords): 0.911 vs 0.875, 7 vs 7 missed, p95 19.8 s; the intervals overlap. Default stays tiny.
* **Forced language vs automatic language ID:** forcing the clip's language is an oracle (the product does not know the language of the answer) and was never selectable; on test it would add about 0.02 (0.900 vs 0.875). Restricting automatic ID to English / Mandarin changed nothing measurable (0.873 vs 0.875).
* **Supervised intent did not help:** character n-gram models trained on the 58-phrase legacy corpus or on the 156 dev phrases reach 0.38-0.61 on test (25-28 of 38 calls missed). The conservative combination (a help cue from either wins; REASSURANCE only if both agree) scores 0.744 with 5 of 38
  missed and the lowest TV / visitor reassurance rate (9 of 80 instead of 17): it trades recall of REASSURANCE for caution. Rule v2 alone is better on the headline numbers; the combination stays a candidate if the cancel-eligibility step needs a stricter reassurance reading.
* Product change: **`audio.intent_method` = `rule_v2`** (was the v1 rule, still selectable as `rule`). ASR model (tiny), decoding (plain) and language handling (automatic) are unchanged. Median ASR time 0.61 s, p95 1.2 s over speech and noise clips of this test (the slowest, a noise clip, 6.8 s),
  well inside the 10 s listening window and the 30 s ASR timeout.
* **Two runs of this protocol on this machine** (same phrase bank, voices and noise clips; the variation comes from faster-whisper's default decoding, which retries a decode that looks bad at temperatures 0.2 to 1.0 with random sampling: 13 of 40 appliance-noise clips changed their text between four identical calls in one process, none with temperature 0.0, `scripts/f3_review_analyses.py asr_determinism`; both runs used the default): the product default (tiny, plain, rule v2) scored 0.891 on test in the first run and 0.894 here, the dev-selected hotwords cell 0.878 and 0.875; self calls for help missed by these two cells: 5 and 7 of 38 in the first run, 5 and 7 here; the pre-change baseline is identical (first run 0.480 and 23 of 38, here 0.480 and 23). ASR timings differ more (median 0.78 s in the first run, 0.61 s here; p95 1.5 s and 1.2 s) and so does the noise probe (above), so differences of about 0.01 in macro-F1 and a clip or two in the probe are run-to-run noise, not findings. The noise-probe counts and the long decodes (5-15 s) of the biased cells come from that random fallback and were not re-measured with a fixed temperature, so they are indicative only.
* Not established: anything about older adults, accents, dialects, real distress, reverberation, microphone distance or real TV. The synthetic voices are clean and share one engine family.

### 3.3 Cancel-eligibility evidence (A6: voiceprint match + reassurance, how often it would be a false cancel)

Figure 3-3 draws "voiceprint matches -> auto-cancel false alarm"; the approved policy keeps the proposal text, so the gate (`ml/audio/cancel_gate.py`) only produces `cancel_eligible` **evidence** and nothing acts on it
(A5: an EMERGENCY stays EMERGENCY/OPEN whatever the flag says). A6 measures how often that evidence would be wrong. Run `20261008-185642_audio_A6_cancel_eligibility_cac405cb21` (the full-suite run on this machine, 35 min on 16 cores,
protocol in `docs/protocol.md` 8.3): Piper `en_US-libritts_r-medium` renders the English phrase bank in synthetic voices; 150 dev and 150 eval speakers, disjoint, drawn at random from 904; dev speakers say dev-split phrases, eval
speakers test-split phrases (split by paraphrase family); every speaker enrols with three fixed neutral sentences; the eval chain is the product chain (energy VAD, faster-whisper tiny, intent rule v2, gate). 2,370 eval clips:
600 enrolled-speaker reassurances (300 of them again with 5 dB ESC-50 noise), 450 calls for help, 300 visitor-role and 300 TV-role reassurances (loudspeaker simulation), 300 replays, 100 household sounds, 20 silences.
Gate: at least 1.0 s of speech, intent REASSURANCE, ASR avg_logprob >= -1.0, speaker score (cosine, WeSpeaker VoxCeleb ResNet34-LM) >= threshold.

* **Thresholds, chosen on dev speakers only** (clean clips with >= 1 s of speech: 215 genuine and 32,035 impostor trials): FAR 0.1% -> cosine 0.682 (dev TAR 0.679); FAR 1% -> 0.605 (dev TAR 0.940). The 10,000-trial rule for FAR 0.1% is met by the trial count only: the 32,035 trials are 215 probes against about 149 enrolments each, so the threshold rests on 215 independent probes. A two-way speaker bootstrap puts it anywhere in [0.665, 0.700], which on the eval speakers would have given a FAR of 0.12% to 0.04%. The dev probes are also shorter than the eval clips: only 36% of the 600 dev probes reach 1.0 s of speech (median 0.90 s), against 78% of the 600 eval clips (median 1.14 s).
  On the disjoint eval speakers the strict threshold gives FAR 0.08% [0.06, 0.10] (55 of 69,583; trial-level Wilson interval, too narrow because the trials are not independent) with a two-way speaker-bootstrap interval of [0.04, 0.13]%, and 0.1% lies inside both; TAR 62.5% [58.1, 66.8] (292 of 467); the loose one FAR 0.63% and TAR 89.9%. Eval EER 2.5% (467 / 69,583 trials).
  Speaker-layer EER by seconds of speech (dev | eval): < 0.75 s 7.9% | n/a, 0.75-1 s 4.2% | 2.4%, 1-1.5 s 1.8% | 2.1%, 1.5-2 s 2.2% (45 genuine) | 0.9%: the 1.0 s minimum is a modest choice, not a sharp one (probes under 0.75 s are clearly worse on dev, but 0.75-1 s is no worse than 1-1.5 s on the eval speakers).
* **Scenarios at the strict operating point (FAR 0.1%).** Trial = one clip scored against one enrolled user, so a clip from another person is tested against up to 149 voiceprints. Wilson intervals treat trials as independent (too narrow); the
  speaker-bootstrap interval resamples speakers. The two rows without events count clips, not trials: each of the 100 household-noise clips and 20 silences is tested against 150 users, but whether a noise clip is read as
  REASSURANCE does not depend on the user, so the independent units are the clips and the interval is computed on them.

  At the looser point (FAR 1%, threshold 0.605): enrolled reassurance 60.0% (noise 38.7%), another person 0.41% [0.29, 0.55], visitor 0.74%, TV 0.09%, replay **17.0%**, noise-only and silence 0, help 0.
* **What the voiceprint adds.** The words alone would let another person (or the TV) cancel in 78-89% of the trials, because they really contain reassuring words (A3b); with the gate it is 0.0-0.1%. None of the 100 household-noise clips and 20 silences reached REASSURANCE (per-clip upper bounds 3.7% and 16.1%), but 48 of the 100 noise clips came out of Whisper as a hallucinated
  transcript ("Thank you for watching.", "Brilliant.") that passed the energy VAD, so the protection against noise is the intent layer, measured on 100 clips.
* **What it costs.** The real user is accepted only 42% of the time at FAR 0.1% (60% at 1%), 21% in 5 dB noise. For the 600 clean trials the blocking reasons (overlapping) are: `too_short` 133 (22%: "Fine", "Okay, thanks", "Yes, fine" are about 1 s or less of speech),
  `intent_not_reassurance` 69 (12%), `speaker_mismatch` 275 (46%). Without the voiceprint the same gate would pass 67% (400 of 600): the voiceprint removes 25 points of true cancels.
* **Replay is not detected as such.** 5.3% (strict) to 17.0% (loose) of replays are eligible. This is channel mismatch, not liveness detection: the crude loudspeaker simulation (200-4000 Hz band-pass and a synthetic room) lowers the score of the user's own voice, and the same
  mismatch is why the live user in 5 dB noise is accepted far less often. A recording that reaches the microphone without a loudspeaker or a room (a voice message, a call) would be accepted as often as the live reply (42%). Anti-spoofing is out of scope.
* **Calls for help.** 0 of 450 eligible [0, 0.85%], but this protection is the intent layer, not the voiceprint: the enrolled voice passed the voiceprint in 61% of these clips (274 of 450), the words were read HELP in 405, OTHER in 45 ("Aiyo, my back" 40 of 40) and REASSURANCE in 0.
  Only 14 distinct phrases, and the lexicon author had seen them: with the 13 cues that fire only on test wording switched off, the words are read HELP in 328 of 450 clips (OTHER in 122) instead of 405, still 0 eligible;
  visitor reassurance read as REASSURANCE falls from 262 to 227 of 300 and the enrolled user's own reassurance (531 of 600) does not change. A3b (SAPI voices) read 2 of 62 HELP-labelled clips as REASSURANCE (mixed sentences), so the eligible rate for HELP in the user's own voice is not zero in general: it is the intent error rate times the voiceprint acceptance, about 0 to 2%.
* **Real-speech transfer check** (26 LibriSpeech speakers, 208 genuine / 5,200 impostor trials of 2.5 s probes, speaker layer only, nothing tuned on it): at the TTS-calibrated thresholds the real-speech FAR is 0 of 5,200 [0, 0.07%] at both points (the 5,200 trials come from 208 probes, the independent units: 0 of 208 gives an upper bound of 1.8%) and TAR 83.2% [77.5, 87.6]
  (strict) / 93.8% (loose); real EER 0.04% (208 genuine trials resolve only 0.5%, so read it as under 1%). Synthetic voices are the harder impostors (impostor mean score 0.246 against 0.100), so TTS-calibrated thresholds are conservative for clean read speech. They say nothing about phone-quality, noisy, short or elderly speech.
* **Reliability.** FAR 0.1% needs at least 10,000 impostor trials to mean anything: dev had 32,035, and the eval FAR (0.08%) agrees with the target, and a speaker bootstrap of it [0.04, 0.13]% contains 0.1%. These pairs come from 150 speakers and are not independent, hence the wider speaker-bootstrap intervals; the dev side is only 215 probes (above). The 450 HELP, 300 replay and 600 true-cancel
  trials are single clips, so their rates are noisier than the 89,400-trial rows; zero events are bounded by the Wilson upper limit only.
* **Consistency audit:** the product gate (`CancelGate.evaluate` on the audio) disagreed with the vectorised analysis in 0 of 199 random trials. `rescore` (`python -m homeease.experiments.audio_cancel rescore <run dir>`) reproduces every number from the saved per-clip table (labels, transcripts, scores; no audio and no embeddings).
* **Three runs of the same protocol and the same speakers (seed 42): what Piper's sampling noise moves.** The first run (`20261008-113720_audio_A6_cancel_eligibility_cac405cb21`) was started on a code state that was edited while it ran (gate, inquiry wiring, report code); `rescore` of its saved table with the final analysis code reproduces every one of its saved metrics exactly. The first run gave thresholds 0.679 / 0.601, enrolled reassurance eligible 42.3% [38.4, 46.3] (5 dB noise 19.3%), another person 0.06% (50 of 89,400), TV 1 of 44,700, replay 4.3% (17.7% at the looser threshold), calls for help 0 of 450, consistency audit 0 of 199.
  The second run (`20261008-132958_audio_A6_cancel_eligibility_cac405cb21`, final analysis code) is the one behind the demo thresholds of `homeease audio replay`. The second run gave thresholds 0.686 / 0.604, enrolled reassurance eligible 39.0% (5 dB noise 18.0%), another person 0.04% (32 of 89,400), TV 3 of 44,700, replay 2.7% (15.0% at the looser threshold), calls for help 0 of 450.
  The third run is the full-suite run quoted above. Across the three, the same speakers and the same words moved the true-cancel rate over a range of 3.3 points (39.0% to 42.3%) and the replay rate over a range of 2.7 points (2.7% to 5.3%), which is the size of uncertainty to attach to the single-clip rows (about the width of their Wilson intervals); the false-cancel rows for other persons and the TV stayed below 0.1% in all three. The cause is Piper's default sampling noise (`noise_scale` and `noise_w_scale`, both 0.333 for this voice), which is not seedable but can be switched off: `HOMEEASE_PIPER_DETERMINISTIC=1` sets both to 0 and makes the synthesis bit-identical (speaker 5, one phrase: 18,391 and 18,205 samples with the default sampling, 18,205 twice and bit-identical with it off); the three runs used the default sampling, and a run in the deterministic mode is not comparable with them.
* **What this does not show.** Everything is synthetic, clean, English, from one TTS engine family (imitations of read audiobook speakers); no older adults, accents, dialects, real TV, room acoustics, microphone distance or session-to-session voice change. Mandarin is not evaluated (no multi-speaker Mandarin voice within
  the download budget). Piper's default sampling noise is not seedable, so a rerun differs (see the bullet on three runs above; a deterministic mode exists and was not used). `audio.voiceprint.threshold` ships as `null`: nothing is eligible until a household-specific calibration with real, consented voices exists.
* **Policy consequence.** Even with these figures the decision stays: evidence only. If automatic cancellation were ever considered, the numbers say it would rarely fire for the real user (42%), can be fooled by a replay without channel mismatch, and depends entirely on the intent layer for calls for help.
